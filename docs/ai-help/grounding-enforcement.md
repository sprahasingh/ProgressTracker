# AI Help grounding rollout

The Edge Function reads `AI_HELP_GROUNDING_ENFORCEMENT`, which remains disabled by default. Independently of that global rollout switch, factual claims are enforced when retrieval finds both a matching capability and current source excerpts. If any claim in that covered answer is missing or rejected, only accepted claim text may be returned; otherwise AI Help abstains and offers the in-chat support form. Other low and medium risk answers remain in shadow mode until the broader rollout is evaluated. Grounding failures increment the aggregate `grounding_failure` metric. Request text and claim text are not written to diagnostics.

High-risk account deletion and destructive-action instructions fail closed when claims, current cited evidence, capability prerequisites, or rendered availability are missing or inconsistent, even in shadow mode.

To enable deterministic claim enforcement after the adversarial suite has been reviewed, set the Edge Function environment value to `true` and redeploy `ai-help`. In enforcement mode, any missing or rejected factual claim returns a concise uncertainty response. The model's evidence references and lexical overlap checks are not semantic proof. Keep enforcement disabled until production-like evaluation shows that supported answers are not being rejected at an unacceptable rate.

Capability metadata is in `src/features/ai-help/capability-definitions.json`; router paths are generated from `src/routes/router.tsx`. UI runtime observations are emitted only by controls carrying `data-ai-capability`, and contain capability IDs plus `available`/`disabled` states. The frontend also sends the generated capability version. The Edge Function uses observations only when that version matches; missing or mismatched versions mean availability is unknown. Older clients remain accepted conservatively. These fields do not contain tracker values or personal content.

The chat handles greetings, thanks, and goodbyes locally. Short follow-up messages use bounded recent conversation context; only earlier user messages can be used to prefill an escalation. Assistant responses are conversational context, never evidence. A support query is sent only after the user reviews the editable form and chooses **Send Query**. It uses the authenticated `send-feedback` function, the canonical support recipient, and the account email as Reply-To. The database stores no support message text. Migration `20261030000100_ai_help_support_query_metrics.sql` adds content-free aggregate `support_query_accepted`, `support_query_failed`, and `support_query_uncertain` outcomes; apply it before deploying the updated `send-feedback` function.

Regenerate all versioned AI Help bundles with `npm run build:ai-help-bundle`. The generator checks capability evidence paths and verifies that app navigation and assistant links resolve to router paths. The knowledge, source, capability, and frontend version bundles share one version; the Edge Function rejects mismatches among its bundles. For rollout, deploy `ai-help` before the frontend: the new function accepts older clients without a version, while an older function rejects the new version field.
